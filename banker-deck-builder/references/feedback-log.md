# Feedback log (what the user praised, corrected and asked for)

Evidence from the Project Print engagement, in order. Use it to calibrate: these reactions show what "good" means
to this user.

## Praised
- Situation overview built from a detailed spec: "this slide is great" (asked only to add a 2030 bar and footnote
  that maturity figures include amortization).
- Capital structure plan: "make sure to make it visually appealing and matching to the other slides... creative but
  clean like the other ones."
- Business plan slide: "awesome... probably the least edits I've had to make on any of your slides." What it did:
  four modules, each one chart with one message, explained well, consistent with the first two content slides.
- Comps plan: "I like that... make sure to keep telling the story."
- Liquidation slide: "great slide."
- The deck overall: "you have done a fantastic job of building this out."

## Asked for (standing instructions)
- "Creative but clean. Emphasis on graphs but explaining them well and making sure we are telling a story through
  each slide and sticking to the clean formatting of the other slides, especially the first 2 content slides."
- "Lay out exactly how you want [the slide] laid out and how it's achieving telling the story, then you can go
  forward." / "Say what you are going to do and what is going where."
- "Make our conclusion clear and succinct and have it wrap up the story we are telling well." (recommendation)
- Include peer logos when possible; the user fills any that cannot be pulled.
- "Where you can, just put the Excel outputs in [the appendix], because if you don't it looks very Claude, but
  we can have some good information/slides in there as well. Put what we need and what would help us."
- When offering alternatives: "don't delete the old one and I can pick."
- Fix the model first when a slide exposes a model problem, then build the slide.

## Corrected
- "In general don't use we or any personal pronouns" on slides.
- Never use em dashes or other AI-writing tells.
- Didn't love a text-heavy recommendation slide (banner + tranche table + alternatives cards + 8-item grid);
  replaced with charts that land the conclusion (before/after, why the fulcrum signs, path to emergence, terms).
- Appendix proposals that read like extra main slides "don't really feel like appendices": appendix = model outputs
  plus brief commentary.
- Callout fill debate: grey fill for commentary boxes, white for pills on charts (adopted as the system).
- When the user edits a slide, they want an honest "what got better / what to reverse" split, with reasons.
- When another model produced a version: compare honestly, adopt what is better, keep what is better in yours,
  refuse unsourced figures.

## Model-building preferences (they shape the numbers on the slides)
- Models must be "very easily followable, readable, clear and clean"; simpler is better; match the user's existing
  formatting exactly; notes go in cell comments, not in note columns; no unnecessary summary blocks.
- In RX, valuation is shown as EV (not price per share) because claims are paid from EV.
